Cue — macOS setup

Requires macOS 14 or later. This image is built for the architecture in its filename (arm64 = Apple Silicon).

1. Drag Cue.app onto Applications, then open it from Applications.
2. Cue opens Settings → Setup. Review recording permission first; recording starts disabled. Optional AI processing has its own consent. Chrome handles Meet microphone permission; optional Calendar access is requested only when you connect Calendar.
3. Setup checks the extension connection, local speech model, and selected AI provider’s installed tools. Reuse the existing model or choose Download speech model (approximately 824 MB). Download only missing tools for the selected provider if you want AI features. Model downloads no longer start silently on first launch. Provider sign-in and account limits are separate from installing tools.
4. In Cue Settings, open Connect Chrome and choose Prepare extension and open Chrome. New installations prepare the extension in Cue Extension in your Home folder (~/Cue Extension). In your existing Chrome profile, enable Developer mode and click Load unpacked. Press ⌘⇧H, select Cue Extension, and click Open. Or use Copy folder path in Cue, then ⌘⇧G in Chrome’s folder picker, paste, Return, and Open. Copy the extension’s ID into Cue.
5. Cue no longer creates a separate Chrome profile. Any profile and data created by 0.1.4 are left intact. The Cue Extension folder on this disk is included for inspection or manual copying; do not load it directly from the mounted disk image.
6. Existing users: previously prepared linked installations keep their current folder, including older Application Support locations. Use Show extension folder or Copy folder path in Cue. Keep the current extension ID and unpacked folder to preserve browser history. Do not install a duplicate extension. Update/reload only outside a call.
7. Eject this disk after installation. Your calls and downloaded model are kept separately from the application.

Check the release notes for this image’s signing and notarization status. Local source builds use ad-hoc signing by default; release builds can use Developer ID signing. Signing alone is not Apple notarization, and macOS may block a downloaded image that is not notarized.

AI summaries and coaching download the selected provider’s pinned tools on first use (internet required). Settings shows setup progress and lets you retry. Tools are cached in your Application Support folder, separately from the app. Only the selected provider is downloaded. These features use the separately configured provider; the speech model download does not include cloud AI credentials or subscriptions.
